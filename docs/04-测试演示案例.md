# 测试演示案例

> 目的：新用户 15 分钟内跑通全链路，验证系统功能完整。
> 前置：后端(8787)、演示靶站(8899)、前端(5173) 均已启动（启动命令见 `03-部署运行教程.md`）。

## 演示靶站说明

`tests/demo_site.py` 模拟一个带已知漏洞的小型业务站（127.0.0.1:8899）：

| 接口 | 方法 | 读写 | 演示点 |
|------|------|------|--------|
| `/api/items?id=` | GET | 读 | **布尔盲注注入点**（sqlmap 可确认，产出真漏洞） |
| `/api/search?q=&page=` | GET | 读 | 多参数读接口（AI 研判打分对象） |
| `/api/login` | POST | 写 | 写接口（探测自动限 technique=BET） |
| `/api/order/submit` | POST | 写 | 写接口 + 链路成员 |
| `/api/user/profile` | GET | 读 | 无参数接口（低风险，应低分） |

首页 HTML 含表单与 JS 内引用的路径，用于验证静态爬虫提取能力。

## 案例一：全链路闭环（核心演示，约 5 分钟）

**步骤：**

1. **登录** `http://localhost:5173`（admin/admin123）
2. **配置**（首次）：扫描配置页
   - 授权范围添加：名称 `demo`，类型 `ip`，范围 `127.0.0.1`
   - AI 接入：可跳过（走规则引擎）；演示 AI 能力则填 DeepSeek 等 OpenAI 兼容接口
3. **建任务**：任务面板 → ＋新建任务
   - 名称 `演示-全链路`，目标 `http://127.0.0.1:8899`，采集方式 `仅静态爬虫`
   - 探测强度 `中`，两个引擎勾选 → **创建并启动**
4. **观察**：实时日志抽屉自动打开，SSE 滚动显示采集/WAF/研判/探测各阶段日志；
   任务状态 `collecting → scanning → review`
5. **研判**：AI 研判页 → 对复核队列逐条点「确认扫描」
   （队列清空后系统**自动触发续扫**，提示「已恢复扫描」）
6. **结果**：漏洞结果页出现 `SQL注入·布尔盲注 GET /api/items`（待复核）
   - 点「证据链」：payload / WAF 画像 / 请求特征 / sqlmap 控制台输出，每条带 SHA-256
   - 点「确认」：漏洞转已确认，成功 Payload 自动回流知识库
7. **报告**：点「导出加固报告」下载 PDF（含漏洞详情 + 加固建议）

**预期结果：** 产出 1 个待复核漏洞 → 确认 → 知识库 payload +1 → PDF 报告可下载。

## 案例二：未授权目标拦截（安全管控演示，1 分钟）

1. 任务面板新建任务，目标填 `http://unauthorized.example.com`
2. 点启动 → **预期返回 403，任务停在 created 不产生任何探测请求**
3. 审计日志页可见本次拒绝记录

**说明：** 体现「授权范围是硬约束」——不在范围内的目标连探测请求都不发。

## 案例三：误报回流与负样本压制（AI 学习闭环，3 分钟）

1. 跑一次案例一（或用已有 review 态任务）
2. AI 研判页对某条目点「误报」→ 预期：条目移出队列 + 知识库「误报样本」Tab +1
3. 重跑同类任务 → 该接口的研判分数被压低（风险分显著下降，理由含负样本命中）

**说明：** 人工复核的误报判断沉淀为负样本，持续压制同类误判——系统越用越准。

## 案例四：AI 能力对比（可选）

1. 扫描配置页配置 AI（如 DeepSeek：`https://api.deepseek.com/v1` + key + `deepseek-chat`）
2. 建新任务跑全流程 → AI 研判页底部显示 `研判引擎：{ "provider": "openai-compatible", "model": "deepseek-chat" }`
3. 清空 AI 配置再跑一次 → 显示 `provider: rule-engine`

**说明：** 同一系统两种引擎的研判粒度对比；无 key 环境功能不缺失。
