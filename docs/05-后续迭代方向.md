# 后续迭代方向

> MVP（七步计划 1–6）已交付：采集 → 建模 → WAF 画像 → AI 研判 → 注入探测 → 证据归档 → 报告，
> UI 端到端闭环实测通过。本文列出按优先级排序的迭代方向，供后续版本规划。

## P0 —— 补齐 MVP 遗留

### 1. Burp Java 插件（已推迟项）
- **内容**：Java 原生 Burp Suite 扩展（`--release 16` 编译，适配用户 BP 的 jdk16），
  监听 Proxy 流量，去重后 HTTP 回调推送 `/api/burp/push`。
- **现状**：后端推送 API 已实现且冒烟通过（幂等去重），可先 curl 手动喂流量。
- **要点**：推送失败本地缓冲重试；多 BP 实例并发；敏感 Header 脱敏。

### 2. 扫描前自动重跑链路还原
- **背景**：Burp 流量在静态爬虫之后到达时，L1/L2 链路缺 Burp 部分（2026-10-13 待办）。
- **内容**：探测调度批次启动前统一重算 business_chains，而非依赖采集时点。

## P1 —— 能力扩展

### 3. 漏洞类型扩展
- 当前仅 SQL 注入（sqlmap + AI Payload）。候选：
  - **XSS / SSRF / 命令注入**：AI Payload 生成器已具备模板框架，扩展模板即可；
  - **越权 / IDOR**：结合已有「会话链路 + 读写分类」数据做换账号对照——
    数据基础（business_chains、凭证指纹聚类）已在建模层就绪，是投入产出比最高的方向。

### 4. AI 引擎增强
- **多轮研判**：当前单轮 chat_json；可引入「探测结果 → 再研判」闭环，误报率进一步下降；
- **Payload 进化**：把知识库成功样本做向量化检索（当前为规则匹配 + 前缀检索）；
- **研判解释性**：输出置信区间与判定依据引用（命中哪条负样本/哪个链路特征）。

### 5. Burp 流量深度利用
- 会话凭证自动识别（Cookie/Token 字段名学习），完善 L2 聚类；
- 响应体差异特征入 WAF 画像（当前以响应头/状态码为主）。

## P2 —— 工程化

### 6. 多用户与角色
- 当前单管理员种子账号；扩展 user 表的角色（审计员只读/操作员/管理员）与行级数据隔离。

### 7. 任务并发与调度升级
- 当前单任务后台线程；扩展为任务队列（多任务并行、优先级、全局限速窗口）。

### 8. SQLite → PostgreSQL 迁移
- SQLAlchemy 已隔离方言，切换成本低；触发条件：单库证据/日志超过千万行级。

### 9. 报告增强
- 模板化报告（Word/HTML）、按任务聚合多漏洞对比视图、修复验证（复测回归）章节。

## 迭代原则（沿用 MVP 的约束）

- 每个迭代完成后回归 smoke_1/2/3/4 四套冒烟，全绿才合入；
- 安全管控（授权硬约束/熔断/限速/写接口限制）不因任何功能迭代放松；
- AI 相关功能必须保留**无 key 降级路径**，系统不允许强依赖外部服务。
